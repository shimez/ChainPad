# OBS Media Tester

ChainPadへの実装前に、OBS WebSocket 5.xのメディア再生制御・再生位置変更・音量調整の挙動を調べる独立したPython GUIです。
ChainPad本体は不要です。PythonからOBSへ直接要求を送ります。

## Windowsで起動

Tcl/Tkを含むpython.org版Python 3.11以降を使用してください。

```powershell
cd tools/ObsMediaTester
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe media_tester.py
```

OBSの「ツール」→「WebSocket サーバー設定」でサーバーを有効にし、ポートとパスワードを確認します。
同じPCのOBSはHost `127.0.0.1`、別PCならそのPCのIPアドレスを指定します。既定ポートは`4455`です。

## 操作

1. 接続するとOBS／WebSocketのバージョンを表示し、`GetInputList`を実行します。
2. 対象入力ソースを選択します。既定ではメディアソース（`ffmpeg_source`）とVLC（`vlc_source`）を表示します。
   「メディア / VLCのみ」を解除すると全入力を選べます。外部プラグイン等のソース名は手入力も可能です。
3. 再生・一時停止・停止・先頭から再生・次へ・前へを実行できます。
4. 絶対位置と相対移動は**秒単位、小数第3位まで**入力します。APIへは整数ミリ秒で送ります。
   相対移動は負数で戻ります。「−10秒」「＋10秒」も利用できます。
5. 「状態取得」で再生状態・位置・長さを確認できます。「0.5秒ごとに取得」を有効にすると継続取得します。
6. 再生・位置操作の完了後（OBSの失敗応答も含む）には、同じ対象の状態を1回取得します。
   遷移直後の結果なので、必要に応じて少し待って再取得してください。
7. 通信ログをUTF-8で保存できます。要求・応答・OBSエラーコード・コメント・往復処理時間を記録します。

ソース一覧は名前で選択します。取得時の`inputKind`／UUID等は通信ログで確認できます。
ソースの改名・追加後は「一覧取得」を押してください。

### 音量調整

再生制御と同じ対象入力ソースを使用します。マイクなどを操作する場合は「メディア / VLCのみ」を解除してください。

- **スライダー**：動かすと絶対音量を送信します。送信間隔は最短100msで、応答待ち中も動かせます。待機中の変更は最新値1件にまとめ、最後に指定した値を送ります。
- **− 減少／＋ 増加**：指定した増減幅を、OBSから取得した現在音量に加減算します。例：50%から5ポイント増加で55%。結果は0〜100%に制限します。
- **指定音量に設定**：入力した絶対音量に設定します。小数も指定可能です。
- **音量取得**：OBSの現在音量を%とdBで表示し、スライダーを更新します。設定成功後も1回取得します。音量取得のみではOBSの値を変更しません。

%は線形振幅倍率（`inputVolumeMul` × 100）です。100%=0 dB、50%≒−6.02 dB、0%=無音であり、OBSフェーダーの移動距離の割合ではありません。ミュート状態は変更しません。OBS側で100%を超えている場合は実値を表示し、スライダーのみ100%に収めます。

相対変更は `GetInputVolume` → `SetInputVolume` の2要求です。両要求の間にOBSや他クライアントで音量を変更した場合、その変更と競合する可能性があります。対象変更・切断で未送信の音量操作を破棄し、取得失敗時は相対設定を行いません。
音声以外のソースを選んだ場合のエラーは通信ログに表示します。音量テスト時は再生状態の「0.5秒ごとに取得」をOFFにしておくとログを確認しやすくなります。

## 確認できるAPI

| API | 送信するrequestData |
|---|---|
| `GetInputList` | `{}` |
| `TriggerMediaInputAction` | `inputName`, `mediaAction` |
| `GetMediaInputStatus` | `inputName` |
| `SetMediaInputCursor` | `inputName`, `mediaCursor` |
| `OffsetMediaInputCursor` | `inputName`, `mediaCursorOffset` |
| `GetInputVolume` | `inputName` |
| `SetInputVolume` | `inputName`, `inputVolumeMul` |

`mediaAction`は`OBS_WEBSOCKET_MEDIA_INPUT_ACTION_`にPLAY／PAUSE／STOP／RESTART／NEXT／PREVIOUSを付けた値です。

## 実OBSで試す項目

| 試験 | 観察する内容 |
|---|---|
| 再生 → 一時停止 → 再生 | 同じ位置から再開するか |
| 再生 → 先頭から再生 | 先頭へ戻るか |
| 停止／自然終了後にPLAYとRESTART | ソースごとの違い |
| 再生中に絶対位置／相対移動 | 移動後も再生を続けるか、位置の精度 |
| 一時停止中に位置変更 → 再生 | 一時停止を維持し、指定位置から再開するか |
| 停止中に位置変更 | OBSの失敗応答とコード（通常604） |
| 先頭より前／末尾より後へ相対移動 | 補正・停止・終了などの実際の挙動 |
| VLCで次へ／前へ | プレイリスト切り替え、ループ設定との関係 |
| 非表示・非アクティブのソースを操作 | OBSのソース設定との相互作用 |
| 存在しない名前／非対応ソース | エラー応答、または成功しても動作しない場合 |
| OBS終了／接続切断 | GUIが固まらず、操作が自動再送されないこと |
| 音量スライダーを連続操作 | OBSの音量追従、最後の指定値への到達 |
| OBS側で音量変更 → 増加／減少 | 最新のOBS値を基準にすること、0/100%での制限 |
| 指定音量を0／50／100%に設定 | 無音／約−6.02 dB／0 dB、ミュート状態が変わらないこと |

テスト時はOBSバージョン、ソース種類、ループ・非アクティブ時の設定、再生ファイルを記録すると比較しやすくなります。

## 動作の範囲

- このツールは実際にOBSを操作します。表示／非表示は変更しません。
- 同じ入力ソースを複数シーンで共有している場合、再生状態も共有されます。
- NEXT／PREVIOUSやシークの対応はソースに依存します。成功応答だけで操作結果を断定せずOBS画面と合わせて確認してください。
- シーク時に長さを取得して末尾へ補正することはしません。入力した値をそのまま送ってOBSの挙動を観察します。
- 再生状態取得で長さ／位置がnullの場合は「不明」と表示します。
- 通信は別スレッドで直列実行し、待機中は操作ボタンを無効にします。状態取得の要求も重ねません。
- 応答待ちは5秒です。タイムアウト後は結果未確定として切断します。自動再接続・操作の自動再送は行いません。
- 状態確認はポーリングです。イベント購読は行いません。
- ログは最新2000件。パスワード・認証トークンはログに含めず、接続設定のファイル保存も行いません。
  ソース名やOBSの応答内容は含まれます。
- ChainPadのメモリ制約・キュー受付タイミング・実機性能を再現するものではありません。

## 開発用検証

リポジトリルートから、依存パッケージを導入したPythonで実行します（GUIテストにはデスクトップ環境が必要）。

```powershell
tools/ObsMediaTester/.venv/Scripts/python.exe -m unittest discover -s tools/ObsMediaTester -v
```

モック通信で認証フロー・応答照合・失敗・切断時の再送なし、Tk GUIで選択・位置変換・状態表示・音量の絶対/相対指定・上限下限・スライダー最新値送信・対象変更時の中止を検証します。
実OBSでの再生結果は上の手動試験で確認してください。
