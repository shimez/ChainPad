## 共通手順

1. VRChatでOSCを有効にし、OSC Debugを表示する。検証用のChainPadキーを決める。
2. **一覧から候補を選択**し、Address・Typeが表と一致することを確認する。選択時のValueは目的のテスト値に設定し直す。
3. Press／Releaseへ下記の方式で設定し、「保存・適用」。毎回1候補ずつ試す。
4. OSC DebugでAddress・Type・値・送信順を確認し、VRChat上の変化を観察する。
5. 最低2回繰り返す。1回目だけ動く場合は解放値が届いているか確認する。
6. 結果欄に「○／△／×／保留」を記入し、差異・前提条件・復帰方法をメモする。

**結果の意味**：○＝想定した操作を確認、△＝条件付き／説明と差異あり、×＝前提条件と受信を確認しても動作しない、保留＝対象機能・機器・権限などの条件未成立。未実施は空欄。

### 送信方式

| 記号 | 設定・手順                                                                | 観察すること                                                                  |
| ---- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| I    | Int。最初に0、その後Press=1／Release=0。約1秒保持してから離す             | 0→1時、1の保持中、1→0時を分けて観察。さらにもう1周期試す                      |
| B    | Bool。最初にfalse、その後Press=true／Release=false。約1秒保持してから離す | 押下／保持／解放のどこで実行されるか。さらにもう1周期試す                     |
| S    | Bool。別キーまたは設定変更でtrueとfalseを**独立して**送る                 | true、true、false、falseの順。状態指定か、毎回反転かを確認。Releaseは空にする |
| A    | Float。Press=0.5／Release=0、次にPress=-0.5／Release=0                    | 両方向と0での停止。反応がなければ±1でも確認                                   |
| V    | 表の数値を順番に送る。Releaseは空                                         | UI表示値と実際の変化、境界での動作。テスト後は元の値へ戻す                    |
| F    | String。表の用途に合うファイルパスを送る。Releaseは空                     | ファイルとパスの扱い、処理完了、失敗時の反応                                  |

- 「I」「B」の**動作タイミングは未確定の検証対象**です。押下時に動くと決めつけず記録してください。
- 「S」の項目は一度trueを送った後、キーを離しても状態が維持されるかも確認します。
- 同一キーに異なる検証を割り当てる前に、旧Addressの0／falseを送って入力を解除します。設定保存やChain停止は、VRChatへ旧入力の解放値を送る操作ではありません。
- 受信は確認できるが変化しない場合、モード・対象アイテム・ワールド／アバター条件を記録します。
- Iの候補は現行一覧に合わせてIntを使用します。Bool互換の確認を行う場合は別試行として記録してください。

### カメラ操作の同値再送確認（ID 34〜36）

利用者より、追加テストも期待どおりに動作したとの報告あり。

- `Close`／`Capture`／`CaptureDelayed`は、Release側を空にし、Pressからtrueだけを繰り返し送信しても毎回実行できた。
- 操作完了を待って次を送信し、`Close`では毎回カメラを開き直して確認。
- 先のtrue／false双方で実行される結果と合わせ、今回の環境ではfalseへの復帰は不要と判断する。
- 一覧の「trueで実行し、次の操作のためにfalseへ戻す」という説明は実測と異なるため、修正対象（コードには未反映）。

説明文案：

> true／falseのどちらを送信しても実行されます。Press側だけに設定し、Release側への送信は不要です。同じ値を繰り返し送っても実行できます。

### FlySpeed追加テスト（ID 64）

利用者によるChainPad実機・VRChat上の追加確認結果。送信型はFloat。
VRChat上の初期表示速度は3.0だが、OSCで3.0を送信すると表示速度は15.0になった。

| OSC送信値（Float） | VRChatの表示速度 |
| ------------------ | ---------------- |
| 0.0                | 0.1              |
| 0.1                | 0.2              |
| 0.25               | 0.8              |
| 0.5                | 3.9              |
| 0.75               | 7.7              |
| 1.0                | 15.0             |
| 3.0                | 15.0             |

**実測からの整理**

- 今回の環境では、0〜1のOSC入力で表示速度0.1〜15.0を調整できた。中間値の変換は線形ではない。
- OSCが速度そのものではなく、正規化されたスライダー位置を受け取っている可能性が高い。ただし、内部実装・正確な変換式は未確認。
- 1.0と3.0はいずれも表示速度15.0となった。その他の範囲外入力の扱いは未確認。
- Wikiの0.1〜15という記載は、OSC入力範囲ではなくUI上の速度範囲に対応する可能性がある。VRChat側の不具合か、資料と実装の不一致かは未確定。
- 結果は「△（資料・現在の一覧説明との差異あり）」として維持する。表示速度3.0へ戻すためにOSCで3.0を送らず、必要ならVRChatのUIで元の速度へ戻す。

**一覧の説明文案（未反映）**

> 0〜1で飛行速度を調整します。0で最小速度0.1、1で最大速度15.0。中間値は非線形に変換されるため、送信値と表示速度は一致しません。
