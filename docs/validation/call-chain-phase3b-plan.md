**既に十分な保護。** `CallModel.parseFile` はCallの整数表記も検査し、Fullは `Presets.read`、Keyは貼付後の仮の全体に対し直接／間接循環を検査する。保存時は編集内容を複製し `Presets.read` を通してからHTTP保存を始める。これらは編集時の予防とは別の最終防壁であり、緩めない。調査時に `node tests/test_call_model.cjs` と `node tests/test_call_preset_ui.cjs` はともにPASS。後者はVM・代替DOMによる原子性の証拠で、実画面のフォーカス、表示、実機の証拠ではない。

## 段階と受入条件（実施には別途承認）

1. **編集ガードと拒否理由（P1＋関連メッセージ）。** 既存のモデルを使い、自己除外・2入力および3入力の循環・Loop内Call・既定先が循環・全候補不可・正常な先への変更をホストで確認。拒否時は旧Actionの固有フィールド、他の未保存編集、選択中の入力、編集カード、dirtyの真偽を保持し、HTTP書込み0件。成功時は要約とdirtyが更新され、完了後も保存までは本体に未反映。対応なしの能力フラグ、CallからOSC等への変更、保存・Importの既存拒否も回帰確認。`tests/test_call_model.cjs`／`tests/test_call_preset_ui.cjs` を再利用し、UIイベントの確認にはローカルConfiguratorで実DOM操作を加える。実機不要。**この境界で挙動・メッセージをレビューし1コミット候補。**
2. **選択欄の視認性（P2、P3は採否次第）。** ネイティブselectを維持し、全IDが同じ先を指すこと、自己除外、キーのPress/Release・Encoder Push・CW/CCWの区別、空の先、小画面・キーボードで判別できることをローカルで確認。英語のイベント名と日本語補足を並べ、折り畳み／Loop内の要約、削除・並べ替え・正常なKey貼付の絶対IDが変わらないことを確認。`tests/test_loop_model.cjs`、`tests/test_presets.cjs` と既存Callテスト、通常のWeb資産組込みを確認。データモデル、schema v2、Key Preset v1、API、Engine、OBS一覧取得処理は変更しない。実機不要。**表示差分と受入結果でレビューし独立コミット候補。**

   - **編集保護：** 実ブラウザーで有効な未保存変更（別キーのAction等）を作り、入力・カード・値・要約・dirty・保存前の実機設定を記録。範囲外IDはselectに不正な選択肢を足さず、`targetInput:28` のFull/Keyファイルから投入。間接循環はKey貼付で初めて成立する例 `A→B→C→A` と、通常の先変更の両方を試す。直接循環も対照。拒否メッセージ、前後の全編集内容、保存API呼出し0件、実機設定不変、その後の正常編集・保存・読戻しを確認。**UI判定**は編集内容と操作結果、**API判定**は3Aの不正値拒否・active設定保持の証拠を別欄に記す。API無変更なら再送試験は不要。VM合格やHTTPエラーのみでUIをPASSにしない。
