# C5 OBS assembly外部配置：第1段階 合格

通常C5アプリSHA256 `05539ccbf1aaf26ad5267719df45b044e06c37a077bcccecb9050e3fb1fd46a5`。ELF上で内部BSSの16,400 B本体が4 Bのポインタと1 Bの試行フラグに置換され、sceneBuffersは8,344 Bのまま。実機 `OBS assembly: base=0x421f7134 bytes=16400 externalRange=1`。初期化はOBSワーカー生成前、実行時の再確保なし。参照はWebSocket受信済みバイトのコピー、同期パース、制御状態のみで、組み立て領域をWi-Fiや周辺機器のDMAへ渡す経路なし。

前回と同じ224 Action設定、Wi-Fi接続・BLE MIDI/HID購読あり・OBS未接続を各試行前後に確認。各起動で小設定GET、初回stage～commit、待機/status/設定GET×4、保存→設定GET×3を実施。各設定GETは全内容一致。1回目とソフト再起動後の2回目の双方で全区間の割当失敗カウンタは0→0。計14回の224枠GET。A＋Cのみの通常版は同条件1起動で1件の失敗。

シリアルmのINTERNAL|DMA|8BIT最大連続空き（区間の前後）は1回目36,852～47,092 B、2回目36,852～45,044 B。A＋Cのみで記録された1,588 Bは失敗時点の値であり、今回の区間境界の最小値と同じ種類の最悪値ではない。送信中の瞬間的な下限は未測定。主判定は通常版の全割当失敗増分とGET内容一致。タイムスタンプはPCの操作時間であり物理入力遅延ではない。

元v0.8.0の全8 MiBと設定を事前退避・照合。第1段階終了後にアプリ領域・LittleFSを戻し、再起動を挟んでflash照合、元設定GET・capabilities一致、ready・稼働0を確認。バックアップはリポジトリ外。第2段階の実機試験は未実施。
