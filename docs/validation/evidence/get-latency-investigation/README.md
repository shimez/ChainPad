# 設定GETとOSC到着間隔：ESP32-C6での版間比較

**1パス版でも、大きな `GET /api/config` と重なると次のOSCがPCに届くまでの間隔が延びた。** 200 msのWaitを挟んだ同一の連番で、Aの `2 → 3` はGETなしで中央値201 ms、config GET時に657 ms。全版の本測定360件は欠落・重複なく順序どおりに届いた。

[Call Chain Phase 3AのC6検証](../call-chain-phase3a/c6/supplement.md)では、GET中の約1.64秒の到着空白に加え、正式版v0.13.0でもLoopを使った共通負荷で約1.8秒の空白を観測した。そこで本調査では、Loop導入前・GETの2パス化前にも同様の現象があるかを、**LoopもCallも使わず**に調べた。以前の秒数は異なる負荷の観測であり、以下の集計には含めていない。Phase 3Aの合否とは独立の資料である。

- [実装と比較バイナリ](implementation-history.md)：どの変更の前後を比べたか。
- [試験方法・データの読み方](test-plan.md)：共通fixture、測定時計、実施回数、判定条件。
- [結果と制約](results.md)：GET単体、接続条件を揃えた再測定、OSC併用45試行。
- [測定データ](data/)：HTTP応答そのものではなく、各試行の観測量、OSC連番・受信時刻、診断差分、復元照合結果。

**終了判断：既知の実行特性として記録し、現時点で性能改善を必須としない。** 想定する通常利用では設定全体の取得とOSC操作が重なる機会は限定的と考える。これは利用頻度を実測したという意味ではない。必要が生じた場合に、この記録を回帰比較の基準とする。HTTP最適化・非同期化・タスク分離、あるいは事前検査の削除を今回の結論とはしない。
