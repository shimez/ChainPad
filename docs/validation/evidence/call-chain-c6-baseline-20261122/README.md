## 試験と復元

- 変更前の公開設定JSONを作業用ローカル領域に保存（元バイトSHA256 `b883d416b625388a470399a0e345d63ef30abdd7ef963eb1a6564dd2fcb52710`）。Wi-Fiパスワードは取得せず、保存時も省略して維持。OBS設定は変更せず、一時起動したPC側OBSは計測後に終了。
- 通常設定を保存した後、13組のPress/Releaseを16/0、CW/CCWを各8とし、192バイトのOSCアドレスと128バイトの引用符・バックスラッシュ入り値で224枠を埋めた。保存・GETで設定全体を比較。最大構成のOSCはトリガーしていない。
- 32枠試験は別設定で `Loop(999) → Wait(60000 ms) → Loop End` をHTTPで32回起動。設定GETを重ね、シリアルとHTTP双方で32を確認。別ChainのStopとPanicは別試行で各32→0。連続送信負荷・物理入力遅延を測る試験ではない。
- 再起動後、周期診断OFFでも224枠の連続保存を実施し、最大構成・元設定とも再起動後のGET一致を確認。別途、OFFでの連続保存の前後を手動診断で採取（`repeat-off`）。2回目保存後に `minFree=50496`。復元後、EdgeでConfiguratorをロードして「保存済み」とKEY 01表示を確認し、再度GET一致。割当失敗・入力/transport overflow・Invocation拒否の記録なし。
- `h` の主試験終了時最低未使用スタック：loopTask 5264 B、input-scan 2652 B、chainpad-obs 3532 B。設定保存の一時オブジェクトが生きている瞬間のlargestは測れていない。B案の可否は未判定。

## ログの読み方

- `pre-obs-{m,h}.log.txt`：再起動前、OBS未接続の別起動セッション。主試験の累積最低値と混同しない。
- `serial.log.txt`：主試験。`@@` はPC側の工程境界。デバイス時刻は起動後ms。`normal-save` から `load-setup` 途中まで周期診断ON。
- `repeat-off.log.txt`、`browser-done.log.txt`：周期診断OFF・手動スナップショット。後者は復元後のブラウザ操作。
- `status.csv`：生のHTTP statusから抽出した稼働数・累積カウンタ・OBS状態。再起動で累積値はリセット。シリアルのIPv4表記は伏せた。設定バックアップ・生ログはリポジトリに含めない。
