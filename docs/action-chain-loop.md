# Action Chain Loop

Loopは、内部のActionを指定回数だけ繰り返す機能です。
回数は**合計実行回数**で、1〜999を指定します。Loopの中にLoopを置くこともできます。

## Configuratorでの操作

1. 「＋Add Action」でActionを追加します。
2. 編集欄の「Action」から「Loop」を選びます。
3. 初期状態は回数3・内部が空のLoopです。内部の「＋Add Action」から操作を追加します。

- 見出しの「Loop」で内部を折りたたみ・展開します。
- ↑／↓は同じ階層内を移動します。「移動先…」ではLoopの内外へ移動できます。
- Loop見出しのドラッグは、展開・折りたたみにかかわらず内部ごと移動します。
- ドラッグ中に折りたたまれたLoopへ650 msホバーすると展開します。
  Escでキャンセルすると配置と自動展開前の状態へ戻ります。
- 「Loop解除」は囲みだけを外し、内部Actionを残します。
- 「削除」はLoopの内部も削除します。
- 変更は「保存・適用」で本体へ反映します。開閉状態は保存しません。

## Action枠

LoopのHeader／Footerはそれぞれ1枠、合わせて2枠を使います。
普通のActionから空Loopへの変更には追加で1枠必要です。

- Press／Release合計：16枠
- CW／CCW：各8枠
- 空Loopも作成できます。

## 実行と停止

- Waitも毎回実行します。最後の周回のWaitも省略しません。
- 同じキーの再入力は別の実行として開始します。最大32個を同時に保持します。
- WaitなしLoopも実行量を区切って続行するため、全周回を一度に実行しません。
- Loop入りChainのOSCは全実行共通で4 msに1回を上限とし、到達順に送信を許可します。
  順番待ちではActionや残り回数を消費しません。LoopなしChainはこの制限の対象外です。
  満杯時の受付例外で実行するStopまでの直線部分は、従来の受付動作を優先します。
- 「他のChainを中断」は、到達するたびにその時点の他の実行を止め、
  自分のLoopは残り回数を継続します。既に送った操作は取り消しません。
- 満杯時は原則として新しいLoopを受付しません。Loop／Wait／ペア送信より前に
  「他のChainを中断」がある場合は、その直線部分で枠を解放して開始できます。
  Loopの中にあるStopでは、この受付例外にはなりません。
- 「実行中止・HID解除」（Panic）はLoopを含む実行と未処理出力を破棄します。
- Backendの受付失敗時は従来どおり次のActionへ進み、成功するまで再試行しません。

## 設定・Preset

Full／Key PresetへLoopを含められます。既存のLoopなしPresetも使用できます。
旧Firmware／旧ConfiguratorはLoop Actionを認識できません。
旧版へ戻す場合はLoop導入前のバックアップを使用してください。

ネストした999回Loopは非常に長時間動くことがあります。
回数の積による自動打切りはありません。終了させる場合はPanicを使用します。
