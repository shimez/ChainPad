# ミュート対象の手動一覧取得

## 仕様

- `SetInputMute` / `ToggleInputMute`の自由入力欄に、シーンと同じ一覧選択パネルを追加。
- 「ミュート対象一覧から選択」を押したときだけ`GetInputList`を実行する。
- ミュート設定のAction／OBS操作／入力名／ミュート対象候補／ミュートはPCでは5列。
  画面幅1100 px以下では2列とし、横スクロールを不要にする。
  候補パネルは項目群の後の独立した全幅行に配置し、開閉によって項目の配置を変えない。
  ミュート切り替えはPCでは4列、画面幅1100 px以下では2列にする。
  画面幅700 px以下ではシーン切り替えを含む全Actionの編集項目を2列に統一する。
  候補一覧や説明文は独立した全幅行に表示する。
- `inputKindCaps & 2`（OBS_SOURCE_AUDIO）の入力名を候補にする。
  公式obs-websocket 5.6.0でこのフィールドを確認済み。5.5.2にはない。
- フィールドがない／型が不正な入力があれば、取得全体を
  `audioCapabilitiesUnavailable`として失敗させる。旧v5への個別照会・Batch・再試行は行わない。
- 空一覧は正常な取得結果。非音声入力は件数枠を消費しない。
- 名前はUTF-8 1–192 bytes、候補32件、名前領域4096 Bまで。
  上限超過・不正名・JSON確保失敗では部分一覧を公開しない。
- 有効な完全一覧に名前がない場合だけ赤字で警告する。保存は許可する。
  未取得／失敗／期限切れの場合は不在と断定しない。
- Config / Full / Key Presetは従来の`inputName`文字列を保存する。
  UUID・一覧・ミュート状態の取得値を保存しない。内部取得要求はActionとして登録できない。

## 通常Action優先

シーン取得にも同じ優先制御を適用する。

1. 通常要求がキューにある時は、新規一覧取得をBusyとして返す。
2. 取得要求を取り出した時に後続要求があれば、取得を送信せず失敗させる。
3. 取得の応答待ち中に後続要求があれば、次のWorker周期で取得待ちを打ち切る。
4. 後続要求がなくても一覧の応答待ちは250 msで打ち切る。自動再試行しない。
5. 打ち切りは接続を閉じない。遅れて届く応答はrequest IDで除外する。
   通常Action待ち中に届く大きな遅延応答は、上限付きのJSONフィルタで
   envelopeのみ確認し、名前一覧を展開しない。

250 msはアプリケーションの応答待ち期限であり、厳密な実時間上限ではない。
Worker周期、受信・JSON処理の実行時間は別に存在する。
既存WebSocketsのTCP read/write timeout（1000 ms）、不完全フレームや
通信障害の処理は引き続き適用される。送信済み要求をOBS側で取り消すものでもない。
OSC/MIDI/HIDの処理経路は変更しない。

## 共有バッファと所有権

- 既存の`SceneList[2]`を両種別で共用する。名前バッファの追加なし。
- Workerは非公開スロットのみを書き、loopはID/generationを確認して交換する。
- 同時取得は1件。別種別の取得要求はBusy。同種別の連打は集約する。
- 本体の公開キャッシュは1種類。別種別の成功時に置き換え、以前の種別の
  HTTP応答には名前を出さない。古いスロットへの別ポインタは保持しない。
- UIも1つの取得managerを共用。種別変更時に候補を破棄し、進行中の旧HTTP応答を
  epochで無効化する。起動／再接続／編集切り替え時の自動取得はしない。
- Assembly 16400 B、Worker stack 8192 B、一覧解析JSON予算32768 Bは維持。
  受信上限16384 Bは全入力応答に適用されるため、音声候補が少なくても
  大量の非音声入力があるOBSでは取得できない場合がある。

## HTTP

- `GET /api/obs/inputs`：本体キャッシュを取得。OBSへは送信しない。
- `POST /api/obs/inputs/refresh`：手動取得を要求。本文なし。
- シーンAPIと同じstate/complete/requestId/generation/error/ageMsを使用し、
  名前配列は`inputs`。受付202、競合429、利用不可503。
- 主な取得エラー：`audioCapabilitiesUnavailable`、`listLimitOrInvalid`、
  `actionPriorityOrTimeout`。失敗時も入力名は編集・保存可能。

## 実機確認

自動テストとリンクサイズ測定は、実機のヒープ／スタック余裕の代替ではない。
S3/C5/C6で次の確認が必要。

1. OBS 5.6系以降：マイク、デスクトップ音声、音声付きメディア、映像のみの入力で候補を確認。
2. 旧v5：非対応案内、手入力保存、既存ミュートAction実行を確認。
3. `o`で既存メモリ測定を予約し、入力一覧を取得、`O`と`m`で採取。
   診断名は従来のscene表記だが、入力一覧取得でも同じ測定を使用する。
4. 32件付近・長いUTF-8名・大量の非音声入力で反復取得し、internal
   free/minFree/largest、PSRAM、Worker stack HWM、確保失敗を比較。
5. シーン／入力一覧を交互に取得し、候補の混入・古い参照・継続的なメモリ減少がないことを確認。
6. 取得中のOSC→OBS→HID等の混在Chainで、OBS側受信時刻を含め遅延を測定。
   遅延応答・途中フレーム・通信障害時も確認する。

実機未測定のまま、バッファ／受信上限／JSON予算／スタックを拡大しない。
